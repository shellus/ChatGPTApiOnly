# 架构、应用行为与验证范围

## 模块

| 模块 | 职责 |
| --- | --- |
| `crates/core` | 配置、凭据、快照、代理、四文件保存、历史修复、启动计划 |
| `crates/cli` | 参数、确认、输出和退出码；调用核心 |
| `src-tauri` | IPC、窗口生命周期、后台修复和进度事件 |
| `ui/src` | React + Radix Themes 表单、内存草稿、显示与确认 |

核心不依赖 Tauri。默认 workspace 只构建核心和 CLI，Linux 无 GUI 依赖。SQLite 编译进二进制，不调用 Windows 专用 DLL。平台差异集中在 `launch.rs`。

## 操作契约

| 操作 | 行为 |
| --- | --- |
| 打开 | 只读取到内存，不写配置，不启动；按记住的窗口几何还原 |
| 编辑 / Tab / 列表 | 只修改草稿；恢复原值不再视为修改 |
| 保存 | 校验四文件基线、结构、认证和路由；成功留在窗口 |
| 启动 | 阻止草稿和外部变化；只读取活动认证；请求成功才退出 |
| 关闭 / 标题栏 / Esc | 共用确认，默认继续编辑，不撤销已保存配置 |
| 修复 | 明确确认后备份和修复；不保存表单，不启动 |

不使用自动启动、倒计时、全局空格或 Enter 默认启动，不停止既有客户端，也不添加启动器单实例锁。`operation.lock` 只串行化本工具写入，不阻止多个窗口打开。

窗口几何在移动和缩放时记入内存，退出时写 `launcher-profiles/window.json`；最大化与最小化期间只更新最大化标记，保留手动调整过的还原尺寸。该文件不在四文件基线内，不参与保存与启动校验，写失败只记日志。还原前核对可见显示器，窗口中心不落在任何显示器上时放弃记住的位置。

## 配置和认证

GUI 保存请求显式携带当前客户端；校验和应用当前客户端，以及另一个客户端中实际修改过的草稿。未改动的另一客户端不重写、不因其地址或认证校验失败阻塞当前保存。IPC 顶层兼容字段始终对应 Codex，Claude 表单只写入 `draft.claude`。

快照包含四文件原始字节和缺失状态，revision 使用长度分隔的 SHA-256。保存前整体核对，并在逐文件替换前再次核对。同目录临时文件 flush/sync 后原子替换，失败逆序恢复。外部再次改变已写文件时不覆盖，报告回滚错误。

`toml_edit` 保留未知字段、其他提供者和嵌套表。官方模式只留下精简 custom 定义；完整片段保存在 API 条目的 `model_providers_toml`，重复保存不以精简定义覆盖快照。显示名称不是 ID；名称精确为 `OpenAI` 可能触发上游特殊行为，本工具不将它解释为模式选择。

认证由 `auth.json` 决定。不写 forced_login_method；显式限制、非 file 存储、选中的 profile、冲突路由或 custom 认证覆盖阻止应用。官方启动不携带自定义 Key、地址或域名阻断；允许无令牌进入登录，部分损坏令牌阻止操作。JWT 只用于身份提示。

外部 API 按地址和 Key 匹配条目；无法匹配时创建独立导入草稿，保留原条目身份。只读导入使用稳定 ID，使 CLI `list` 返回的 ID 可供下一条命令使用，不依赖隐式保存。历史 ID、配置 ID 和显示名称独立。

## 历史修复

逐行扫描 rollout，待修改内容暂存临时文件，保留其他行、换行及修改时间。备份先于任何修改。SQLite 在线备份包含已提交 WAL 内容，不直接复制运行中的 WAL/SHM。

只纳入含目标历史表及 provider 字段的数据库，无关数据库不进入写事务或备份。目标数据库作为 ATTACH 库加入同一事务，先执行全部 SQL，再替换 rollout，最后提交。SQL、文件冲突或替换失败时回滚数据库，并恢复已改写 rollout；恢复前核对内容以免覆盖外部写入。最多支持 10 个目标数据库，超限阻止。

## 验证范围

- 核心：保存/启动分离、四文件外部变化、写入失败逐点回滚、快照往返、登录捕获与退出、部分凭据阻止、外部 API 归属、代理校验/幂等/父环境隔离、路由冲突、备份/WAL、幂等、多数据库与文件失败回滚。
- CLI：实际二进制添加、重命名、导出冲突、启动计划、修复确认。
- Web 界面：草稿、失败与重试、三个关闭入口、修复确认、浅深色、紧凑窗口和大文本。
- Windows 正式 GUI：fixture、实际 IPC、保存与外部冲突、取消关闭和 Esc、退出记住窗口几何与再次打开按记住尺寸还原；脚本不进入正式二进制。

CI 在三个系统运行核心/CLI 回归，构建 Windows/macOS GUI。构建和 fixture 测试不等同于真实账号联网或真实客户端启动验证。

## 仍需关注的边界

- 多客户端界面的默认窗口高度适配待修复：`npm test` 的 `settings fit desktop, compact window and large text in both themes` 用例在 640px 高度下未通过页面无纵向溢出的断言；需核对客户端选择区的高度预算并同步界面截图。
- Rust 全仓库格式检查存在未统一的历史格式，涉及 CLI、Claude 和存储模块；需独立执行格式整理。
- 外部 Codex 不参与操作锁；基线核对与替换间仍有竞争窗口，多文件保存也不是掉电原子事务。
- SQLite ATTACH 在 WAL、崩溃或掉电条件下不保证跨库提交原子性；备份提供恢复依据。修复应停止客户端写入后执行。
- rollout 扫描流式处理，但替换/冲突核对阶段仍读取完整文件；极大文件峰值内存待评估。
- 窗口打开后的 OAuth 刷新会触发外部变更阻止，需重新读取。
- Windows 包 EXE 访问被拒绝时明确报错，不使用会丢失参数与环境的 Explorer 激活回退。
- macOS 真实 Codex 启动、联网、菜单和多显示器仍需对应机器实测；无发布凭据时不声称完成 Apple 签名/公证。
