# 应用行为与验证范围

## 窗口与操作

| 操作 | 行为 | 验证 |
| --- | --- | --- |
| 打开应用 | 只显示设置；读取失败报告具体操作错误，不启动客户端 | 入口检查、窗口回归 |
| 编辑、选择与重命名 | 修改草稿；显示名称不改变 provider ID | 账号/API 管理回归、无落盘断言 |
| 保存 | 保存当前选择与配置库草稿；留在窗口；不启动客户端 | 四文件写入与失败回滚回归 |
| 启动 | 有未保存修改、外部变化或活动配置冲突时阻止；只使用活动认证 | 两种模式启动、失败与重试回归 |
| 关闭、标题栏关闭、Esc | 共用关闭事件；未保存时默认保留编辑，明确放弃后退出 | 关闭按钮与关闭事件回归；Esc 绑定同一按钮 |
| 修复对话 | 确认范围后将本地 provider ID 归入 custom；不保存表单 | 取消不执行、备份、幂等、单数据库失败回滚、真实进度回归 |
| 商店与更新 | 仅打开对应商店入口，失败时浏览器回退 | 链接、取消与回退回归 |

## 界面一致性

- 保存按钮表达保存状态，启动按钮不显示“正在保存”。
- 字段修改后不继续显示“已保存”；恢复原值后可识别为未改变。
- 名称缺失、空白时仍能选择、重命名和删除。
- 保存与读取失败使用对应操作描述，不统称启动失败。
- 两种 Tab 检查控件边界与重叠；修复区域额外检查放大到 150% 后的边界。
- 截图只来自隔离的 example 配置窗口。

## 尚未覆盖的运行边界

- 外部配置在窗口打开前的身份归属、非完整 OAuth 凭据与退出登录的区分。
- OAuth 正常刷新目前触发保守的外部变更阻止，需要重新打开设置。
- 读取基线检查不构成跨进程事务，检查后写入前仍可能有竞争。
- 历史修复的多数据库整体回滚与运行中 SQLite/WAL 一致性备份。
- 未以真实账号请求或所有 Windows DPI/多显示器组合验证；隔离测试不等同于这些验证。

上述边界必须保留在后续维护范围中，不以现有回归通过声明不存在问题。
